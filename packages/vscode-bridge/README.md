# MCP Hub Bridge

VS Code extension that exposes **this** VS Code window to a locally running [MCP Hub](https://github.com/ydiaz1699/MCP-hub).

The Hub holds the single MCP server that Claude Code, Claude Desktop, Cursor and other MCP
clients connect to. This extension is the **bridge**: it receives semantic operations from the
Hub (open a file, edit the selection, run a terminal command, start a debug session, ask the
language server for definitions…) and performs them through the official VS Code Extension API.

## How it fits together

```text
MCP client (Claude / Cursor / …)
        │  MCP (Streamable HTTP)
        ▼
     MCP Hub            127.0.0.1:8765
        │  local RPC (loopback only)
        ▼
  MCP Hub Bridge        127.0.0.1:8766   ← this extension
        │
        ▼
      VS Code
```

## Security

- The bridge listens on `127.0.0.1` only — never on a public interface.
- Every request must carry `Authorization: Bearer <token>`, where the token is the one
  generated by `mcp-hub init` (`~/.mcp-hub/config.json`).
- The bridge performs **semantic** actions (open `auth.ts`, select lines 20-35), never raw UI
  automation (no synthetic clicks / coordinates).

## Configuration

The extension reads these environment variables when VS Code starts:

| Variable | Default | Purpose |
|---|---|---|
| `MCP_HUB_BRIDGE_PORT` | `8766` | Port the bridge listens on (loopback). |
| `MCP_HUB_TOKEN` | *(empty)* | Shared bearer token. Must match the Hub's token. |
| `MCP_HUB_URL` | `http://127.0.0.1:8765` | Hub base URL the bridge pushes events to. |

Because VS Code must see these variables, launch it from a shell that exports them, e.g.:

```bash
export MCP_HUB_TOKEN=$(node -e "console.log(require('os').homedir())" >/dev/null; \
  grep -o '"token"[^,]*' ~/.mcp-hub/config.json | cut -d'"' -f4)
code .
```
